How I Built a Gold Price Prediction Model with Python

My first full machine learning workflow, end to end: a real daily dataset, cleaning decisions I had to defend, feature engineering that actually carried signal, and a Lasso Regression model tuned with GridSearchCV and judged with three metrics, not one.

Python Pandas · scikit-learn Lasso Regression Time series 2017-2025
Read the case study More articles

Why gold

I come from business before machine learning. I worked in sales and export for marble and granite companies, and in Egypt gold is a market everyone watches daily. So when I wanted a first serious ML project during my DEPI Machine Learning Engineer track, predicting gold prices felt natural: real data, real stakes, and a target I actually understand.

I used the Kaggle dataset DOJI gold price 2017-2025 (the file DOJI_SG_gold_price_2017_2025.csv), loaded with KaggleHub, and set the target as the daily selling price.

Cleaning: the part nobody posts about

The raw daily data had the usual problems: missing values and outliers. I handled missing values and treated outliers instead of dropping rows blindly, because in a time series every deleted row is a hole in the timeline.

The cleaning decision I am most sure about: I did not use drop_duplicates(). Identical consecutive prices are not duplicate rows, they are days when the market genuinely closed at the same price. Removing them would have thrown away real trading days and distorted the series.

Early on I also hit a KeyError on the date column, which forced me to stop assuming and actually inspect the dataset schema. A boring step that saves hours.

Feature engineering that carries signal

My first attempt was naive: I one-hot encoded the date and currency columns and the data exploded to roughly 5,105 columns. It was slow, sparse, and useless. That failure pushed me toward compact numeric features that describe how prices behave:

  • MA_7 and MA_30: moving averages that capture short and medium trend.
  • Daily_Return: the day-over-day percentage change, a basic momentum signal.
  • Lag features: previous days' prices, so the model sees recent history, not just today.

Few features, each with a reason to exist. That is what actually worked.

Modeling and tuning

I chose Lasso Regression for two reasons: it is a solid baseline for a numeric regression problem, and it does feature selection by itself by shrinking weak coefficients to zero, which suits a dataset with several engineered features.

Instead of guessing the regularization strength, I used GridSearchCV to search for it with cross-validation. My instinct would have picked a value in seconds and been wrong in silence.

Evaluation: three metrics, not one

I evaluated the model with RMSE, MAE and R², and plotted actual vs predicted prices with Matplotlib and Seaborn. Each metric catches a different lie: RMSE punishes big errors, MAE shows the typical error, and R² tells you how much of the movement the model explains at all.

The full technical breakdown, including the stack and decisions, is in the project case study.

What I would tell myself before starting

  • Inspect the schema before writing a single line of cleaning code.
  • Validate inputs before training, not after a failed fit. A missing target column taught me that.
  • Repeated values in a time series are data, not duplicates.
  • Never trust one metric, and never guess a hyperparameter you can search for.
