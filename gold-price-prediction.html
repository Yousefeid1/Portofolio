Gold Price Analysis & Prediction

Predicting gold prices from historical data (2017-2025): cleaning a real-world time series, engineering features that actually carry signal, and training a Lasso Regression model tuned with GridSearchCV and evaluated with RMSE, MAE and R².

Regression Time series 2017-2025 Target: sell_price scikit-learn

Overview

Gold is one of the most traded commodities in Egypt and worldwide, and its price moves daily with the market. This project builds a regression model that predicts the selling price of gold from historical daily data, using the Kaggle dataset DOJI gold price 2017-2025 (file DOJI_SG_gold_price_2017_2025.csv), loaded with KaggleHub.

The goal was not only a working model, but doing the full machine learning workflow properly: honest data cleaning, feature engineering grounded in how prices behave, and evaluation with more than one metric.

Approach

  1. Data cleaning. Explored the raw daily data, handled missing values and treated outliers instead of dropping rows blindly.
  2. Feature engineering. Built features that describe trend and momentum: MA_7 and MA_30 moving averages, Daily_Return, and lag features so the model sees recent price history.
  3. Modeling. Trained a Lasso Regression model. Lasso also performs feature selection by shrinking weak coefficients to zero, which suits a dataset with several engineered features.
  4. Tuning. Used GridSearchCV to search for the best regularization strength with cross-validation instead of guessing it.
  5. Evaluation. Measured performance with RMSE, MAE and R², and visualized actual vs predicted prices with Matplotlib and Seaborn.

Key decisions and lessons

Repeated prices are data, not duplicates. Identical consecutive prices are valid market observations, so I deliberately did not use drop_duplicates(). Removing them would have thrown away real trading days and distorted the time series.

Mistakes that made me better

  • Hit a KeyError on the date column early on, which forced me to inspect the real dataset schema instead of assuming column names.
  • A missing target column bug taught me to validate inputs before training, not after a failed fit.
  • My first attempt one-hot encoded date and currency columns and exploded the data to roughly 5,105 columns. That failure is why the final version uses compact numeric features like moving averages and lags instead.
