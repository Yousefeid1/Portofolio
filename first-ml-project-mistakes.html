5 Mistakes I Made in My First Machine Learning Project

My first real ML project was a gold price prediction model built on daily data from 2017 to 2025. It works now, but only because it failed in instructive ways first. These are the five mistakes that cost me the most time, and what each one taught me.

The mistakes

1. I assumed the column names instead of looking

I wrote cleaning code against the schema I expected, and the script died with a KeyError on the date column. The real column was named differently than my assumption.

Lesson: print the actual schema first. Two minutes of inspection beats an hour of debugging code written against a dataset that does not exist.

2. I discovered a missing target column too late

At one point I only found out my target column was missing when the model fit failed. Everything before that line ran fine, which made the real problem harder to see.

Lesson: validate inputs before training. Check that the target exists, has the right type, and has no surprises, before a single model line runs.

3. I one-hot encoded my way to 5,105 columns

My first feature attempt one-hot encoded the date and currency columns. The dataset exploded to roughly 5,105 columns: slow, sparse, and useless for the model. Most of those columns carried no signal at all.

Lesson: more columns is not more information. The final model uses a handful of compact numeric features instead: MA_7 and MA_30 moving averages, Daily_Return, and lag features. Each one exists for a reason.

4. I almost treated repeated prices as duplicates

In a spreadsheet mindset, identical consecutive rows look like duplicates. In a gold price time series, the same closing price on two days is two real market observations. Calling drop_duplicates() would have deleted real trading days and distorted the timeline the model learns from.

Lesson: cleaning rules depend on the data's meaning, not just its shape. Time series data plays by different rules than a customer table.

5. I guessed a hyperparameter I could have searched for

Lasso Regression lives or dies by its regularization strength. My first instinct was to pick a value and move on. Instead I used GridSearchCV to search for it with cross-validation, and let the data argue with my guess.

Lesson: never hand-pick a number that a search can find. Cross-validation is slower than guessing and cheaper than being wrong.

The pattern behind all five

Every mistake above is the same mistake in a different costume: acting on assumptions before checking reality. The schema, the target column, the meaning of a repeated price, the right regularization strength. The fix is always to look first.
